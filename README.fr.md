## Ce qu'il vous aide à suivre

- Les dépenses personnelles face aux coûts d'exploitation professionnels, sans mélanger les deux.
- La rentabilité réelle de l'entreprise après les retraits du propriétaire.
- Les coûts de survie personnelle minimaux face aux dépenses de style de vie discrétionnaires.
- La dérive budgétaire hebdomadaire avant que les excès de dépense ne deviennent une surprise mensuelle.
- L'autonomie financière de l'entreprise et la capacité de couvrir les engagements à venir.
- La progression de l'épargne et l'accumulation d'actifs aux côtés de la performance opérationnelle.

## Pourquoi j'ai conçu ceci

La plupart des petites entreprises et des travailleurs indépendants n'échouent pas par manque de registres de transactions.

Ils échouent parce qu'ils ne parviennent pas à interpréter correctement ces registres.

Les dépenses personnelles s'infiltrent dans les comptes professionnels. Les bénéfices de l'entreprise paraissent plus grands que la réalité parce que les retraits du propriétaire sont ignorés. L'inflation du style de vie se cache dans des dizaines de petites transactions. [...]

La réponse la plus courante est soit de ne rien faire, soit d'adopter des systèmes comptables qui semblent trop lourds pour un usage quotidien.

J'ai conçu ce cadre après avoir vu à plusieurs reprises le même échec analytique :

> L'argent était suivi.
>
> Les décisions ne l'étaient pas.

Par exemple :

**Avant**

Un chef d'entreprise voit \$12,000 à la banque et en conclut :

> "L'entreprise est en bonne santé."

Aucune distinction n'existe entre :

- les obligations opérationnelles futures,
- les besoins de subsistance personnels,
- la rentabilité de l'entreprise,
- les engagements d'épargne.

Les retraits du propriétaire se produisent au hasard.

Les dépenses personnelles passent occasionnellement par les comptes professionnels.

Le chiffre de trésorerie disponible devient trompeur.

**Après**

Les mêmes \$12,000 sont séparés en :

- \$4,500 d'obligations professionnelles engagées,
- \$2,500 d'allocation pour retrait du propriétaire,
- \$2,000 de dépenses de survie personnelles,
- \$1,500 de budget discrétionnaire,
- \$1,500 d'objectif d'épargne.

La question passe de :

> "Combien d'argent est disponible ?"

à :

> "Quelles décisions peuvent être prises en sécurité ?"

Ce classeur industrialise ce raisonnement.

Ce n'est pas un remplacement de la comptabilité.

C'est un cadre décisionnel réutilisable qui rend les arbitrages financiers visibles avant que les erreurs ne s'accumulent.

### Trois pièges qui surprennent même les opérateurs expérimentés

#### Piège 1 : le solde bancaire équivaut à la trésorerie disponible

Une décision a été prise.

Les dépenses d'expansion ont été approuvées.

La décision reposait sur le seul solde bancaire.

| Mauvaise approche             | Bonne approche             |
| -------------------------- | ---------------------------- |
| Utiliser le solde total          | Déduire d'abord les obligations     |
| Ignorer les engagements futurs  | Calculer l'autonomie opérationnelle |
| Traiter la trésorerie comme non restreinte | Allouer par finalité          |

Le défaut :

La trésorerie et la trésorerie disponible ne sont pas identiques.

Résultat corrigé :

Les décisions d'expansion n'ont lieu qu'après couverture des dépenses engagées.

<details>
<summary>Logique de formule</summary>

```excel
Available Cash
=
Bank Balance
- Committed Expenses
- Planned Draws
```

</details>

---

#### Piège 2 : les dépenses personnelles cachées dans les coûts professionnels

Une décision a été prise.

La rentabilité a été évaluée.

Les dépenses personnelles intégrées dans les comptes professionnels ont déformé les marges.

| Mauvaise approche               | Bonne approche    |
| ---------------------------- | ------------------- |
| Transactions mélangées           | Séparation des entités   |
| Retraits estimés        | Retrait du propriétaire explicite |
| Dépenses ou bénéfices gonflés | Transferts traçables |

Le défaut :

Les entités mélangées détruisent l'interprétabilité.

Résultat corrigé :

La performance de l'entreprise et la consommation personnelle deviennent mesurables indépendamment.

<details>
<summary>Logique de formule</summary>

```excel
Entity
=
Business
OR
Personal
OR
Owner Draw
```

</details>

---

#### Piège 3 : les revues mensuelles détectent les problèmes trop tard

Une décision a été prise.

Les dépenses de style de vie ont continué inchangées.

Les dépassements budgétaires ont été découverts après coup.

| Mauvaise approche             | Bonne approche             |
| -------------------------- | ---------------------------- |
| Découverte mensuelle          | Revues Pulse hebdomadaires         |
| Aucun seuil d'alerte      | Indicateurs précoces             |
| Grandes corrections requises | De petits ajustements suffisent |

Le défaut :

Les boucles de rétroaction arrivaient trop lentement.

Résultat corrigé :

Les excès de dépense deviennent gérables avant de s'accumuler.

<details>
<summary>Logique de formule</summary>

```excel
Discretionary Usage %
=
Actual Spend
/
Budget

Alert Trigger
=
Usage % > 85%
```

</details>

### Scénario d'exemple

Un consultant termine la semaine avec :

| Entrée                    |  Montant |
| ------------------------ | ------: |
| Solde du compte professionnel | $12,000 |
| Coûts SaaS à venir      |    $800 |
| Paiements aux sous-traitants      |  $2,200 |
| Retrait du propriétaire prévu       |  $2,500 |
| Coûts de survie personnels  |  $2,000 |
| Objectif d'épargne           |  $1,500 |

Interprétation intermédiaire :

```text
Business Obligations
=
800 + 2,200
=
3,000

Remaining After Operations
=
12,000 − 3,000
=
9,000

Remaining After Draw
=
9,000 − 2,500
=
6,500

Remaining After Personal Allocation
=
6,500 − 2,000 − 1,500
=
3,000
```

Recommandation :

L'entreprise peut supporter les obligations planifiées et la rémunération du propriétaire tout en préservant les objectifs d'épargne.

Implication décisionnelle :

Les dépenses discrétionnaires supplémentaires devraient rester sous le tampon restant jusqu'à l'arrivée de nouveaux revenus.

Le solde lui-même n'a pas répondu à cette question.

L'allocation structurée l'a fait.

### Règles de validation

| Champ                   | Règle                     | Comportement en cas d'erreur        |
| ----------------------- | ------------------------ | --------------------- |
| Entité                  | Doit être sélectionnée         | Marquer comme en attente       |
| Catégorie                | Doit correspondre à l'entité        | Rejeter la classification |
| Montant                  | Numérique et non nul     | Avertissement de saisie         |
| Date de transaction        | Obligatoire                 | Exclue des rapports |
| Retrait du propriétaire              | Doit relier les entités     | Alerte de validation      |
| Seuil budgétaire        | Alerte au-dessus de 85%        | Souligner le dépassement   |
| Variance de rapprochement | Variance mineure tolérée | Revue requise       |

</details>
